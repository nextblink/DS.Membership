# i18n — Design Spec

**Date:** 2026-05-12  
**Status:** Approved

## Problem

All user-facing strings are hardcoded in English across 17 page components (~600 strings). The app needs to support English and Serbian Cyrillic with a header toggle that persists to localStorage.

## Libraries

```
i18next
react-i18next
i18next-browser-languagedetector
```

No other dependencies needed. No lazy-loading (small app, synchronous resource loading is fine).

## File Structure

```
src/
  framework/
    i18n.js              ← NEW: initializes i18next, imported in main.jsx before React
  locales/
    en/
      common.json        ← nav labels, buttons, pagination, shared
      auth.json          ← login page
      dashboard.json     ← stat cards, chart, org-unit table
      members.json       ← MembersList + MemberForm + MemberDetails/Edit/Create
      forms.json         ← FormsList + FormDetails + FormUpload
      orgUnits.json      ← OrgUnits page
      functions.json     ← Functions page
      users.json         ← Users page
      profile.json       ← Profile page
      enums.json         ← Gender, MaritalStatus, EducationLevel, PhoneType, FormStatus
    sr/
      (same 10 files, Serbian Cyrillic values)
```

## i18n.js Initialization

```js
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import LanguageDetector from 'i18next-browser-languagedetector'

// import all EN and SR json files
// ...

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: { en: { ... }, sr: { ... } },
    fallbackLng: 'en',
    supportedLngs: ['en', 'sr'],
    detection: { order: ['localStorage', 'navigator'], caches: ['localStorage'] },
    ns: ['common','auth','dashboard','members','forms','orgUnits','functions','users','profile','enums'],
    defaultNS: 'common',
    interpolation: { escapeValue: false },
  })
```

`main.jsx` adds `import './framework/i18n'` as its first import.

## Namespace Assignment

| Namespace    | Used by |
|-------------|---------|
| `common`    | Sidebar, Header, shared buttons (Apply/Clear/Save/Cancel/Prev/Next), pagination text, loading/empty states |
| `auth`      | Login.jsx |
| `dashboard` | Dashboard.jsx, StatsCard.jsx, OrgUnitsTable.jsx, FormsStatusDonut.jsx |
| `members`   | MembersList.jsx, MemberCreate.jsx, MemberEdit.jsx, MemberDetails.jsx, MemberForm.jsx |
| `forms`     | FormsList.jsx, FormDetails.jsx, FormUpload.jsx |
| `orgUnits`  | OrgUnits.jsx |
| `functions` | Functions.jsx |
| `users`     | Users.jsx |
| `profile`   | Profile.jsx |
| `enums`     | MemberForm.jsx + FormsList.jsx (status badges) — consumed alongside their page namespace via `useTranslation(['members','enums'])` |

## Component Integration Pattern

```jsx
// Single namespace
const { t } = useTranslation('members')
<h1>{t('title')}</h1>
<button>{t('addMember')}</button>

// Multiple namespaces
const { t } = useTranslation(['members', 'enums'])
<option>{t('enums:gender.male')}</option>

// Interpolation (pagination, sublabels)
t('pagination.summary', { page, total, count })  // "page {{page}} of {{total}} ({{count}} total)"
```

## Translation Key Conventions

- `camelCase` for simple keys: `addMember`, `fullName`
- Dot-separated groups for related keys: `filter.firstName`, `table.fullName`, `error.notFound`
- Enum keys mirror enum names: `gender.male`, `gender.female`, `status.pending`, `status.verified`
- Interpolation variables use `{{variable}}` syntax

## Language Switcher (Header.jsx)

```jsx
const { i18n } = useTranslation()
const toggleLang = () => i18n.changeLanguage(i18n.language === 'en' ? 'sr' : 'en')

<button onClick={toggleLang} className="rounded-md border border-stroke px-2.5 py-1 text-sm font-medium text-body hover:text-primary">
  {i18n.language === 'en' ? 'СР' : 'EN'}
</button>
```

Placed to the left of the user avatar/menu in the header. `i18next-browser-languagedetector` persists the selection to localStorage automatically.
